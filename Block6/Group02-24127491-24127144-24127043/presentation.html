04 · Database

Dish không còn là thực thể đơn lẻ

backend/prisma/schema.prisma
Dish.chefId → Chef.id
DishIngredient(dishId, ingredientId)

Dish  N ───── 1  Chef
Dish  N ───── N  Ingredient

Ràng buộc

Chef: một chef có nhiều dish, mỗi dish có một chef.

Ingredient: bảng trung gian có khóa ghép chống mapping trùng.

Delete: Dish cascade mapping; Chef/Ingredient đang được dùng bị RESTRICT.

Các file SQL 001–004 tách migration, backfill mapping thủ công, enforce NOT NULL và validation query.

06 · Contract giữa BE và SPA

SPA luôn đọc ok trước khi đọc data hoặc error

Success
{
  "ok": true,
  "data": [ ... ]
}
Business error · HTTP 200
{
  "ok": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "fields": { "price": "..." }
  }
}

Code ổn định

VALIDATION_FAILED, NOT_FOUND, CONFLICT, INVALID_ID.

message dành cho developer/log. Frontend map error.code sang tiếng Việt.

fields dùng key trùng name input để render lỗi cạnh field.

07 · Create / Read / Update / Delete

MethodEndpointKết quả source
GET/api/dishesDanh sách, q/category/available, có chef + ingredients.
GET/api/dishes/:idChi tiết theo id, NOT_FOUND nếu không tồn tại.
POST/api/dishesTạo Dish và mapping nguyên liệu trong transaction.
PATCH/api/dishes/:idCập nhật từng phần; mapping ingredients được thay thế nguyên tử khi gửi field.
DELETE/api/dishes/:idXóa Dish và mapping cascade.

Source còn có các trang SPA tương ứng: danh sách, detail, thêm, sửa và xác nhận xóa.

11 · Browser boundary

CORS được kiểm tra như một phần của API contract

BACKEND

Origin cụ thể

http://localhost:5173

Allow methods: GET, POST, PATCH, DELETE, OPTIONS.

Allow header: Content-Type.

FRONTEND

GET không thêm Content-Type

ApiService chỉ thêm header JSON khi request có body.

PATCH/POST kích hoạt OPTIONS preflight trước request thật.

OPTIONS /api/dishes
Origin: http://localhost:5173
Access-Control-Request-Method: POST
Access-Control-Request-Headers: Content-Type
→ 204 + Access-Control-Allow-Origin / Methods / Headers

Rỗng

Lỗi

18 · Kịch bản demo

Trình bày bằng một luồng có bằng chứng

Chạy backend và frontend, mở trang chủ bằng React Router.
Mở Menu, tìm kiếm ?q=Phở, kiểm tra Network chỉ có Fetch/XHR.
Mở detail món, chỉ ra Chef và Ingredients trong response JSON.
Vào admin, tạo/sửa Dish, kiểm tra PATCH và field validation.
Xóa Dish, thử xóa Chef/Ingredient đang được dùng để thấy CONFLICT.
Mở Network kiểm tra OPTIONS trước PATCH/DELETE.
Gọi id không tồn tại để thấy HTTP 200 + NOT_FOUND.
Tắt API để thấy lỗi network/CORS và loading overlay.
